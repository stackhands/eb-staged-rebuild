`verify STAGE` checks a built run's staged trees without publishing them: every ELF object's `DT_NEEDED` resolves inside the stage, the software tree or EESSI (each unresolved library is named with its object), nothing outside `easybuild/` names the build directory or an EasyBuild temporary directory, Lmod loads each staged module file and its `EBROOT*` directories exist, and publishing would not change the tree's owner, mode bits or ACLs. `run --verify` runs the same checks before the swap and refuses a stage that fails unless `--force` is given, and its journal keeps that, so `resume` checks too; `resume --verify` does the same for a run started without it. Without `--verify`, `run` and `resume` publish as before, and refuse `--force`. The journal records the result and whether it was forced, and `runs/<run-id>/verify.json` lists every problem. Like the other commands that take `--state-root`, `verify` falls back to `EB_STAGED_REBUILD_STATE_ROOT`.
