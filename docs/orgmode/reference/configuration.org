* Configuration files

The JSON files eb-staged-rebuild reads besides its options: the ledger configuration of =run=, the configuration and the metadata of =build-events=, and the manifest of =ledger-maintenance backfill=.
On this page an absolute path starts with =/=; a normalized one has no =.= or =..= part, no =//= and no trailing =/=.

** The ledger configuration

=run --ledger-config FILE= names it.
The run keeps the path of the file and its contents in its journal; =resume= and =rollback= read the file again, and refuse with =ledger policy changed; restore the recorded configuration before resuming= when it differs.
The configuration of the example site, from =docs/examples/site.sh=:

#+begin_src bash
cat /opt/site/etc/ledger.json
#+end_src

#+begin_example
{
  "eb_stack": "/opt/site/bin/eb-stack",
  "log": "/opt/site/ledger/stack.jsonl",
  "key": "/opt/site/keys/ledger.pem",
  "public_key": "/opt/site/keys/ledger.pub",
  "head": "/opt/site/ledger-heads/head.json",
  "actor": "alice",
  "stack": "2026.06",
  "target": "x86_64/amd/zen4"
}
#+end_example

| Key          | Default           | Meaning                                                                                                                                                      |
|--------------+-------------------+--------------------------------------------------------------------------------------------------------------------------------------------------------------|
| =eb_stack=   | required          | The absolute path of the eb-stack executable.                                                                                                                |
| =log=        | required          | The absolute path of the ledger, a JSON Lines file, which =eb-stack ledger append= creates.                                                                  |
| =key=        | required          | The absolute path of the Ed25519 signing key, PKCS#8 PEM. eb-stack refuses a key inside the log's directory.                                                 |
| =head=       | required          | The absolute path of the file that eb-stack writes the signed head to after each record.                                                                     |
| =public_key= | none              | The absolute path of the public key. With it, each receipt is also proven with =eb-stack ledger verify=.                                                     |
| =actor=      | required          | Who the records name, such as =alice=.                                                                                                                       |
| =stack=      | required          | The software stack the records name, such as =2026.06=.                                                                                                      |
| =target=     | required          | The target the records name, such as =x86_64/amd/zen4=.                                                                                                      |
| =action=     | =rebuild-inplace= | The =action= of each publication record: =install=, =rebuild-inplace= or =rebuild-bump=. A rollback's records have the action =correction=.                  |
| =required=   | =true=            | With =true=, the directories are exchanged only once every =started= record is acknowledged. With =false=, a run goes on, and the records wait for =resume=. |
| =timeout=    | =120=             | Seconds each eb-stack call may take; a number greater than 0.                                                                                                |

- =actor=, =stack= and =target= must be strings that are not empty.
- Other keys are not used, but are part of the configuration the run compares.
- A value that breaks a rule stops the run before its build with =eb-staged-rebuild: ledger config KEY must be ...=, which names the rule, and exit status 2.

** The build-events configuration

=build-events --config FILE= names it; it holds no metadata of the build, and one file can serve every operation.

| Key            | Default  | Meaning                                                                                                                                                   |
|----------------+----------+-----------------------------------------------------------------------------------------------------------------------------------------------------------|
| =eb_stack=     | required | The eb-stack executable: an absolute, normalized path.                                                                                                    |
| =log=          | required | The ledger, as for =run=.                                                                                                                                 |
| =key=          | required | The signing key: a regular file, not inside the log's directory or the outbox.                                                                            |
| =outbox=       | required | The directory of the operations' records: missing or a directory, reached without a symbolic link, and neither inside the log's directory nor holding it. |
| =public_key=   | none     | The public key; with it, each receipt is proven with =eb-stack ledger verify=.                                                                            |
| =required=     | =true=   | With =true=, the command runs only once its =started= record is acknowledged. With =false=, it runs anyway, and the record waits in the outbox.           |
| =timeout=      | =120=    | Seconds each eb-stack call may take; a number greater than 0.                                                                                             |
| =lock_timeout= | =0=      | Seconds to wait for the lock of the operation's directory in the outbox; 0 refuses at once when another =build-events= holds it.                          |

Paths are absolute and normalized.
A key that is not in this table is refused, as in =build-events: refused: build-event config has fields outside the build-event schema: KEY=.
The signed head of =build-events= goes to =head.json= in the operation's directory, not to the =head= of the ledger configuration.

** The build-events metadata

=build-events --metadata FILE= names it: what one operation builds, at most 1 MiB.
Only these fields go into the records, and a field that is not in this table is refused.

| Key          | Default   | Meaning                                                                                                                                                                                      |
|--------------+-----------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| =operation=  | required  | The operation's name: a letter or digit and up to 127 more of letters, digits, =.=, =_= and =-=, without =..=. It names the operation's directory in the outbox and its records' =event_id=. |
| =actor=      | required  | Who the records name.                                                                                                                                                                        |
| =stack=      | required  | The software stack the records name.                                                                                                                                                         |
| =module=     | required  | The module, such as =Example/1.0-GCCcore-15.2.0=, without white space.                                                                                                                       |
| =location=   | required  | The installation directory, an absolute, normalized path.                                                                                                                                    |
| =target=     | required  | An object: =cpu=, required, and =accelerator=, each names separated by =/=, such as =x86_64/amd/zen4=. The record's =target= is =CPU=, or =CPU/accel/ACCELERATOR=.                           |
| =action=     | =install= | =install=, =rebuild-inplace= or =rebuild-bump=.                                                                                                                                              |
| =easyconfig= | required  | An object: =path=, absolute, and =sha256=. The file is hashed before the command, and a given =sha256= must match it; without =sha256= the file must exist.                                  |
| =sources=    | =[]=      | Up to 256 objects of =name=, a plain file name, and =sha256=.                                                                                                                                |
| =patches=    | =[]=      | The same, for patches.                                                                                                                                                                       |
| =modulefile= | none      | An object: =path=, absolute, and =sha256=. The file is hashed after the command, and a given =sha256= must match; the hash it had before, when it existed, is recorded as =previous_sha256=. |
| =tool=       | none      | An object: =name=, required, =version= and =revision=.                                                                                                                                       |
| =logs=       | =[]=      | Up to 256 objects of =uri=, a URI with a scheme and without credentials, query or fragment, and =sha256=.                                                                                    |
| =artifact=   | none      | An object: =accession=, as =sha256:HEX=, =path=, hashed after the command, and =uri=; =accession= or =path= is required.                                                                     |

- A text field is a string that is not empty, without control characters, of at most 1024 characters; a path may have 4096, a URI 2048, and the fields of =target= and =tool= 256.
- Text that holds =-----BEGIN= is refused as key material: a key never goes in a record.
- A SHA-256 is 64 lower-case hexadecimal digits.
- A second run of an operation must have the same metadata and the same =eb_stack=, =log=, =key=, =public_key=, =outbox= and =required=; otherwise it is refused, and needs a new operation name.

The configuration and the metadata of the example site:

#+begin_src bash
cat /opt/site/etc/build-events.json /home/alice/example-5.json
#+end_src

#+begin_example
{
  "eb_stack": "/opt/site/bin/eb-stack",
  "log": "/opt/site/ledger/stack.jsonl",
  "key": "/opt/site/keys/ledger.pem",
  "public_key": "/opt/site/keys/ledger.pub",
  "outbox": "/opt/site/build-events"
}
{
  "operation": "example-1.0-zen4-5",
  "actor": "alice",
  "stack": "2026.06",
  "target": {"cpu": "x86_64/amd/zen4"},
  "module": "Example/1.0-GCCcore-15.2.0",
  "location": "/opt/site/software/Example/1.0-GCCcore-15.2.0",
  "action": "rebuild-inplace",
  "easyconfig": {"path": "/home/alice/easyconfigs/Example-1.0-GCCcore-15.2.0.eb"},
  "modulefile": {"path": "/opt/site/modules/all/Example/1.0-GCCcore-15.2.0.lua"},
  "tool": {"name": "EasyBuild", "version": "5.4.2"}
}
#+end_example

** The backfill manifest

=ledger-maintenance backfill --manifest FILE --manifest-sha256 SHA256= names it, with the SHA-256 its bytes must have.
It is a JSON object in UTF-8, with no key twice and no number with a fraction.

| Key            | Meaning                                                                                                                           |
|----------------+-----------------------------------------------------------------------------------------------------------------------------------|
| =schema=       | =eb-staged-rebuild/observed-backfill/1=.                                                                                          |
| =manifest_id=  | 1 to 64 letters, digits, =.=, =_= and =-=, starting with a letter or digit. Once backfilled, an id is not taken with other bytes. |
| =observed_at=  | When the observation was made, as =YYYY-MM-DDTHH:MM:SSZ=, and not after the current time: the =ts= of each record.                |
| =observer=     | Who made the observation: the =actor= of each record.                                                                             |
| =stack=        | The software stack; it must be the =stack= of the ledger's first record.                                                          |
| =target=       | The target of each record.                                                                                                        |
| =observations= | A list, not empty, of the installations seen, each module at each location once.                                                  |

An observation:

| Key          | Meaning                                                                                        |
|--------------+------------------------------------------------------------------------------------------------|
| =module=     | Required: the module, such as =Example/1.0-GCCcore-15.2.0=.                                    |
| =location=   | Required: the installation directory, an absolute, normalized path.                            |
| =modulefile= | Optional: an object of =path=, absolute, and =sha256=, both required.                          |
| =provenance= | Required: a list, not empty, of the evidence, objects of =ref=, required, =kind= and =sha256=. |
| =note=       | Optional: text kept with the record.                                                           |

Every key of the manifest itself is required, and a key that is not in these tables is refused.
A text value must not be empty, start or end with white space, or hold a control character.

The manifest of the example site:

#+begin_src bash
cat /home/alice/backfill/audit-1.json
#+end_src

#+begin_example
{
  "schema": "eb-staged-rebuild/observed-backfill/1",
  "manifest_id": "audit-1",
  "observed_at": "2026-11-17T01:50:04Z",
  "observer": "alice",
  "stack": "2026.06",
  "target": "x86_64/amd/zen4",
  "observations": [
    {
      "module": "Example/1.0-GCCcore-15.2.0",
      "location": "/opt/site/software/Example/1.0-GCCcore-15.2.0",
      "modulefile": {"path": "/opt/site/modules/all/Example/1.0-GCCcore-15.2.0.lua", "sha256": "400e56c26dd10f9eb8b0e6b616582cc694614b6758dfddb9849268315e2b4761"},
      "provenance": [
        {"ref": "/opt/site/software/Example/1.0-GCCcore-15.2.0/easybuild/easybuild-Example-1.0-20261117.014923.log", "kind": "easybuild-log", "sha256": "d98f1972c6edb777ca7fe44215b8451abde0102f6d693a08e2c05f1643324408"}
      ],
      "note": "installed before the site kept a ledger"
    }
  ]
}
#+end_example
