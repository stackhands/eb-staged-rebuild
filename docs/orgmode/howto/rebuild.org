* Rebuild an installed module

Rebuild a package that EasyBuild has installed in the site's software tree, and put the new installation in place of the old one, under the same path and the same module file.
A job that starts after the exchange loads the new installation; one that is running keeps the files it has open, which stay on disk under a hidden name.

** Before you start

- eb-staged-rebuild, installed for the account that owns the software tree, as in [[file:install.org][Install eb-staged-rebuild]].
- EasyBuild set up for the tree as for any build of it, with the easyconfig, its sources and the toolchain's modules.
  This guide's site, Example University's, has EasyBuild 5.4.2, its software under =/opt/site/software= and its Lua module files under =/opt/site/modules=, and rebuilds =Example/1.0-GCCcore-15.2.0= from =~/easyconfigs=:

  #+begin_src bash
  export EASYBUILD_SOURCEPATH=/opt/site/sources
  export EASYBUILD_INSTALLPATH_SOFTWARE=/opt/site/software
  export EASYBUILD_INSTALLPATH_MODULES=/opt/site/modules
  export EASYBUILD_MODULE_SYNTAX=Lua
  export MODULEPATH=/opt/site/modules/all:/opt/site/standin/modules/all
  cd ~/easyconfigs
  #+end_src

  =/opt/site/standin/modules/all= holds the =GCCcore/15.2.0= module the package is built with.
  The run puts the tree's own =modules/all= first on =MODULEPATH= for EasyBuild, so the build finds the dependencies installed in the tree with every backend.
- The installation to rebuild, a real directory =software/NAME/VERSION=; a package that is not installed yet is EasyBuild's to install.
- Room for a second copy of the installation on the software tree's filesystem.
  The new tree is built in the /state root/, =/opt/site/.eb-staged-rebuild= unless =--state-root= names another directory, which has to be on that filesystem.

** Steps

1. Ask what this machine and the filesystem of the software tree support:

   #+begin_src bash
   eb-staged-rebuild probe --path /opt/site/software
   #+end_src

   #+begin_example
   bwrap: usable
     version: bubblewrap 0.9.0
   user.max_user_namespaces: 192727
   user-namespace sandbox: usable
   RENAME_EXCHANGE: yes on ext4
   EasyBuild framework: 5.4.2
     bwrap stage-path keys: True (imported)
   filesystem: ext4 /
   lock: local flock lock plus POSIX record lock; cross-node coherence unmeasured
   #+end_example

   =bwrap: usable= and =bwrap stage-path keys: True= mean that the build can run in EasyBuild's bubblewrap sandbox, where it sees the stable path and writes the new tree; =RENAME_EXCHANGE: yes= means that the new tree replaces the old one in one call.

** With =--robot=

It marks =[ ]= those that are not installed, which include the build dependencies of an installed module, here those of the stand-in =GCCcore/15.2.0=; EasyBuild would not build them.

eb-staged-rebuild run --software /opt/site/software --modules /opt/site/modules --run-id example-robot \

A =--robot= run that would install a dependency that is not installed is still refused before anything is built: install it with EasyBuild, then rebuild.
This is the case =robot= of =site.sh=.

** If it fails

A build that fails leaves the installation as it was; [[file:recover.org][Finish a run that failed or stopped]] says what to do next.
These messages come before or instead of a build:

| Message                                                                                                          | Cause                                                                                                                                                                          | What to do                                                              |
|------------------------------------------------------------------------------------------------------------------+--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+-------------------------------------------------------------------------|
| =eb-staged-rebuild: pass the easyconfig after --, for example: ...=                                              | No easyconfig after =--=.                                                                                                                                                      | Put the easyconfig, and any option for EasyBuild, after =--=.           |
| =eb-staged-rebuild: another eb-staged-rebuild holds the lock at /opt/site/.eb-staged-rebuild/.lock=              | Another run, rollback, =gc= or =retire= is using the state root, and =--lock-timeout= ran out.                                                                                 | Wait for it, or give =--lock-timeout= more seconds.                     |
| =eb-staged-rebuild: /opt/site/software/Example/2.0-GCCcore-15.2.0 is missing, not an existing rebuild directory= | =--module=, or a dependency that a =--robot= run would install, names a module that is not installed. A file there is =a file=, and a FIFO, socket or device =a special file=. | Install the module with EasyBuild first, or name one that is installed. |

The first in full, as =site.sh= prints it in its case =no-easyconfig=:
