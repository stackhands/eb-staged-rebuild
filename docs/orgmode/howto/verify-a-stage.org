* Check a rebuild before it goes live

Have a run check its new tree before it goes live, find out why a tree did not pass, correct it, and publish it.
With =--verify=, =run= checks the generation after the build, and after the =--prepare= program when there is one, before it exchanges anything: the shared libraries of each program, the paths of the build and temporary directories, the module files under Lmod, and who may read the new tree.
A generation that fails a check is not published; [[file:../reference/verify.org][The checks before publication]] lists them.
Without =--verify=, a run publishes its tree once the build is complete, as in [[file:rebuild.org][Rebuild an installed module]].

** Before you start

- For the check of the module files, Lmod's =lmod= command in =LMOD_CMD=, as Lmod's own setup leaves it in a login shell.
  Without it that check is skipped, and the report says so.
- For a build on top of EESSI, EESSI's environment, as its =init/bash= sets it, when the run started: the run records =EESSI_CVMFS_REPO= and =EESSI_EPREFIX=, and a library outside the generation, the software tree and EESSI is then a problem.

For a run that already stopped with =verify failed; the live directory was not swapped=, start at step 2.

Here the EasyBuild configuration of the builder has =umask= 077, which makes the new tree of the run =example-6= readable by its owner only:

#+begin_src bash
export EASYBUILD_UMASK=077
#+end_src

4. Correct the new tree where it is, in the generation, and check it again:

   #+begin_src bash
   chmod -R go+rX /opt/site/.eb-staged-rebuild/generations/example-6/software/Example/1.0-GCCcore-15.2.0
   eb-staged-rebuild verify --state-root /opt/site/.eb-staged-rebuild example-6
   #+end_src

   #+begin_example
   eb-staged-rebuild: verify example-6: pass (elf 0, references 0, modules 0, access 0); 0 ELF object(s); report /opt/site/.eb-staged-rebuild/runs/example-6/verify.json
   #+end_example

   A mode, a link or a missing file can be corrected in the generation; a tree that was built wrong, such as against a library that is not there, is better built again by a new run.
5. Publish it:

   #+begin_src bash
   eb-staged-rebuild resume --state-root /opt/site/.eb-staged-rebuild example-6
   #+end_src

   #+begin_example
   eb-staged-rebuild: resume example-6 from built: publishing
   eb-staged-rebuild: verify example-6: pass (elf 0, references 0, modules 0, access 0); 0 ELF object(s); report /opt/site/.eb-staged-rebuild/runs/example-6/verify.json
   eb-staged-rebuild: swapped all/Example/1.0-GCCcore-15.2.0.lua (renameat2-exchange)
   eb-staged-rebuild: published module all/Example/1.0-GCCcore-15.2.0.lua
   eb-staged-rebuild: run example-6 published 1 module(s)
   #+end_example

   The journal records that the run checks its generation, so =resume= checks it once more before the exchange, without =--verify=.

** Check that it worked

The installed program can be read and run by every user, as before the rebuild:

#+begin_src bash
ls -l /opt/site/software/Example/1.0-GCCcore-15.2.0/example-1.0.sh
#+end_src

#+begin_example
-rwxr-xr-x 1 alice alice 29 Nov 17 11:59 /opt/site/software/Example/1.0-GCCcore-15.2.0/example-1.0.sh
#+end_example

=docs/examples/site.sh= in the repository runs these steps as its case =verify=.

** Publish a tree that fails

=--force=, on =run --verify= or on =resume=, publishes a generation that fails the checks, for a problem that the checks report but that does not matter at this site.
The checks still run and the report is still written; the journal's =verify= then has ="forced": true=, and the output says =verify failed; publishing run RUN_ID anyway (--force)=.
Without the checks there is nothing for =--force= to override, so =run --force= without =--verify=, and =resume --force= of a run that does not check, are refused.

** Check a run that was started without =--verify=

A run without =--verify= that stopped before its exchange, such as at a =--prepare= program that failed, is =built= with its generation unpublished.
=verify --state-root DIR RUN_ID= checks that generation without publishing it, and =resume --state-root DIR --verify RUN_ID= checks it before it publishes it.
As the run recorded no build or temporary directories and no EESSI roots for the checks, both take them from the environment they run in.
=resume --verify= records them in the journal, with that the run checks its generation, so a later =resume= checks it the same way.

** If it fails

| Message                                                                                                 | Cause                                                                                                                              | What to do                                                                                          |
|---------------------------------------------------------------------------------------------------------+------------------------------------------------------------------------------------------------------------------------------------+-----------------------------------------------------------------------------------------------------|
| =eb-staged-rebuild: verify: elf: FILE: LIBRARY not found (no RPATH or RUNPATH)=                         | The loader would not find a library that the program or library =FILE= needs.                                                      | Build again with the dependency loaded, or with an RPATH; =(no RPATH or RUNPATH)= says it had none. |
| =eb-staged-rebuild: verify: elf: FILE: LIBRARY resolves to PATH, outside the stage, ...=                | The library comes from somewhere a job on another node may not have, such as the build host's =/usr/lib64=, while EESSI is in use. | Build against the library of the stack.                                                             |
| =eb-staged-rebuild: verify: references: FILE: names PATH, in the build directory DIR=                   | A file outside =easybuild/= names a path in EasyBuild's build directory, which EasyBuild removes.                                  | Correct the file, or the easyconfig that wrote it, and build again.                                 |
| =eb-staged-rebuild: verify: modules: module file REL: Lmod did not load NAME: ...=                      | Lmod refused the new module file, with its own message.                                                                            | Correct the easyconfig, and build again with a new run.                                             |
| =eb-staged-rebuild: verify: access: INSTALL: the staged tree has mode MODE and the live tree MODE; ...= | Without =--prepare=, the new tree would change what group and other users may do with the installation.                            | Correct the modes in the generation, or let a =--prepare= program set them.                         |
| =eb-staged-rebuild: run RUN_ID is STATE; only a built run has a stage to verify=, exit 2                | =verify= checks the generation of a =built= run only: a =complete= run has published it, and a =failed= one has none.              | Check the state with =status=.                                                                      |
| =eb-staged-rebuild: --force needs --verify; ...=, exit 2                                                | =--force= publishes a generation that fails the checks, and without =--verify= nothing checks it.                                  | Give =--verify= as well, or leave out =--force=.                                                    |
| =modules skipped (LMOD_CMD is not set)=, in the line of each check's problems                           | No Lmod to load the module files with.                                                                                             | Set =LMOD_CMD=, and check again.                                                                    |
