* Record any build command in the ledger

Wrap one build command, an =eb= install as much as an =eb-staged-rebuild run=, so that the ledger gets a =started= record before it runs and a =finished= or =aborted= record after.
The records carry the metadata you write for the operation, and nothing of the command or its environment.

** Before you start

- The eb-stack 0.7.0, the key and the log of [[file:record-in-a-ledger.org][Record each rebuild in a signed ledger]].
- An outbox directory where the records wait until the ledger acknowledges them, here =/opt/site/build-events=.
  It must be outside the log's directory.
- A name for the operation that no earlier build has used, here =example-1.0-zen4-5=.
- With the Python package, run =python3 -m eb_staged_rebuild.build_events= where this guide runs =eb-staged-rebuild build-events=.

** Steps

1. Write the configuration, =/opt/site/etc/build-events.json=, and the metadata of the operation, here =~/example-5.json=:

   #+begin_src bash
   cat /opt/site/etc/build-events.json /home/alice/example-5.json
   #+end_src

   #+begin_example
   {
     "eb_stack": "/opt/site/bin/eb-stack",
     "log": "/opt/site/ledger/stack.jsonl",
     "key": "/opt/site/keys/ledger.pem",
     "public_key": "/opt/site/keys/ledger.pub",
     "outbox": "/opt/site/build-events"
   }
   {
     "operation": "example-1.0-zen4-5",
     "actor": "alice",
     "stack": "2026.06",
     "target": {"cpu": "x86_64/amd/zen4"},
     "module": "Example/1.0-GCCcore-15.2.0",
     "location": "/opt/site/software/Example/1.0-GCCcore-15.2.0",
     "action": "rebuild-inplace",
     "easyconfig": {"path": "/home/alice/easyconfigs/Example-1.0-GCCcore-15.2.0.eb"},
     "modulefile": {"path": "/opt/site/modules/all/Example/1.0-GCCcore-15.2.0.lua"},
     "tool": {"name": "EasyBuild", "version": "5.4.2"}
   }
   #+end_example

   The command hashes the easyconfig before it runs, and the module file after; Configuration files lists every key.

** If it fails

| Message                                                                                                                                           | Cause                                                                                               | What to do                                                                                         |
|---------------------------------------------------------------------------------------------------------------------------------------------------+-----------------------------------------------------------------------------------------------------+----------------------------------------------------------------------------------------------------|
| =build-events: aborted: the command exited N=, exit status N                                                                                      | The command failed; the ledger has an =aborted= record.                                             | Fix the build, and record the next attempt as a new operation.                                     |
| =build-events: aborted: the command exited 0; module file PATH cannot be hashed: ...=, exit status 65                                             | The command succeeded, but the module file of the metadata is missing or differs from its =sha256=. | Check =modulefile= in the metadata; the record is =aborted= either way.                            |
| =build-events: aborted: the command could not be started=, exit status 127                                                                        | The command is not on =PATH= or not executable.                                                     | Name the command by its absolute path.                                                             |
| =build-events: finished: the command exited 0; ledger error: N ledger event(s) not acknowledged (...); retry to deliver from DIR=, exit status 75 | The command ran with ="required": false=, and the ledger did not acknowledge the records.           | Fix the cause, then run =build-events= with the same files and =--deliver= instead of the command. |
| =build-events: refused: operation NAME was recorded with different metadata; use a new operation=                                                 | The operation ran before with other metadata.                                                       | Give the operation a new name.                                                                     |
| =build-events: refused: build-event config needs KEY=                                                                                             | =eb_stack=, =log=, =key= or =outbox= is missing from the configuration.                             | Add it, as an absolute path.                                                                       |

A second run of an operation with the same metadata does not run the command again: it delivers what is still pending and returns the recorded result, with =recorded by an earlier attempt; the command was not repeated=.
With the ledger required, which is the default, a =started= record that was not acknowledged stops the command from running, and =build-events= exits 75.
