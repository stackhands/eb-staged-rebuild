* Install eb-staged-rebuild

Install eb-staged-rebuild for the account that builds the site's software with EasyBuild: the static binary of a release, a binary built from source, or the Python package.
All three run the same commands; [[file:../reference/compatibility.org][Compatibility]] lists where their output differs.

** Before you start

- Linux on x86_64 or aarch64, and the account that runs EasyBuild for the software tree.
- For a release binary, =curl= and =sha256sum=, and the GitHub CLI, =gh=, to check where the binary was built.
- To build the binary, Zig 0.17.1 and =git=.
- For the Python package, Python 3.11 or newer and =git=; on Ubuntu, install =python3-venv= for =python3 -m venv=.

** Steps

1. Download the binary for the machine's architecture, =x86_64= or =aarch64=, and the checksums of the release, and check the binary against them:

   #+begin_src bash
   v=2.0.1 arch=x86_64
   curl -fsSLO "https://github.com/stackhands/eb-staged-rebuild/releases/download/v${v}/eb-staged-rebuild-${v}-${arch}-linux-musl"
   curl -fsSLO "https://github.com/stackhands/eb-staged-rebuild/releases/download/v${v}/SHA256SUMS"
   sha256sum --check --ignore-missing SHA256SUMS
   #+end_src

   #+begin_example
   eb-staged-rebuild-2.0.1-x86_64-linux-musl: OK
   #+end_example

2. Check that the binary was built by the release workflow of the repository, from the tag:

   #+begin_src bash
   gh attestation verify eb-staged-rebuild-2.0.1-x86_64-linux-musl --repo stackhands/eb-staged-rebuild
   #+end_src

   #+begin_example
   Loaded digest sha256:f148f6477d3e9d8d60a0a79615a051f15a241a08d14dd1f888bbe60b4327e859 for file://eb-staged-rebuild-2.0.1-x86_64-linux-musl
   Loaded 1 attestation from GitHub API

   The following policy criteria will be enforced:
   - Predicate type must match:................ https://slsa.dev/provenance/v1
   - Source Repository Owner URI must match:... https://github.com/stackhands
   - Source Repository URI must match:......... https://github.com/stackhands/eb-staged-rebuild
   - Subject Alternative Name must match regex: (?i)^https://github\.com/stackhands/eb-staged-rebuild/
   - OIDC Issuer must match:................... https://token.actions.githubusercontent.com

   ✓ Verification succeeded!

   The following 1 attestation matched the policy criteria

   - Attestation #1
     - Build repo:..... stackhands/eb-staged-rebuild
     - Build workflow:. .github/workflows/release.yml@refs/tags/v2.0.1
     - Signer repo:.... stackhands/eb-staged-rebuild
     - Signer workflow: .github/workflows/release.yml@refs/tags/v2.0.1
   #+end_example

   =gh= prints this on a terminal; elsewhere only its exit status, 0, says that the check passed.
3. Install the binary under its own name, and run it:

   #+begin_src bash
   install -m 0755 "eb-staged-rebuild-${v}-${arch}-linux-musl" ~/.local/bin/eb-staged-rebuild
   eb-staged-rebuild --version
   #+end_src

   #+begin_example
   eb-staged-rebuild 2.0.1 (x86_64-linux-musl, safe, zig 0.17.1, 03b695e)
   #+end_example

   The version is followed by the target, build mode, Zig version and commit the binary was built from; the 1.0.0 binaries print the version alone.
4. To build the binary yourself instead, clone the repository and build it with =-Drelease=true=, giving it the commit it is built from:

   #+begin_src bash
   git clone https://github.com/stackhands/eb-staged-rebuild.git
   cd eb-staged-rebuild
   zig version
   zig build -Drelease=true -Dcommit=$(git rev-parse --short=7 HEAD)
   zig-out/bin/eb-staged-rebuild --version
   #+end_src

   #+begin_example
   0.17.1
   eb-staged-rebuild 1.0.0 (x86_64-linux-musl, safe, zig 0.17.1, c44b8ad)
   #+end_example

   Then install =zig-out/bin/eb-staged-rebuild= as in step 3.
   A build of a release's tag gives the release's binary, byte for byte; for 1.0.0, whose build has no =-Dcommit= option yet:

   #+begin_src bash
   git checkout v1.0.0
   zig build -Drelease=true -Dtarget=x86_64-linux-musl
   sha256sum zig-out/bin/eb-staged-rebuild
   #+end_src

   #+begin_example
   c5e0b9908d5835e6ab63e96d41247fec7a83c3a8ea465e4ab0c9a6fa72bb7489  zig-out/bin/eb-staged-rebuild
   #+end_example

   That is the checksum =SHA256SUMS= gives for =eb-staged-rebuild-1.0.0-x86_64-linux-musl=.
5. To install the Python package instead, install it into a virtual environment, from the clone of step 4 and in its directory:

   #+begin_src bash
   python3 -m venv ~/eb-staged-rebuild-venv
   ~/eb-staged-rebuild-venv/bin/python -m pip install --quiet .
   ~/eb-staged-rebuild-venv/bin/eb-staged-rebuild --version
   #+end_src

   #+begin_example
   eb-staged-rebuild 2.0.1
   #+end_example

   Put =~/eb-staged-rebuild-venv/bin= on =PATH=, or link =eb-staged-rebuild= from there into =~/.local/bin=.

** Check that it worked

As the account that builds, ask the tool what the machine and the filesystem of the software tree support:

#+begin_src bash
eb-staged-rebuild probe --path /opt/site/software
#+end_src

#+begin_example
bwrap: usable
  version: bubblewrap 0.9.0
user.max_user_namespaces: 192727
user-namespace sandbox: usable
RENAME_EXCHANGE: yes on ext4
EasyBuild framework: 5.4.2
  bwrap stage-path keys: True (imported)
filesystem: ext4 /
lock: local flock lock plus POSIX record lock; cross-node coherence unmeasured
#+end_example

=bwrap: usable= and =bwrap stage-path keys: True= mean that =run= can build in EasyBuild's bubblewrap sandbox, and =RENAME_EXCHANGE: yes= that it can exchange the new installation with the old one in one call.
[[file:../reference/cli.org][The eb-staged-rebuild command]] describes each line.
When the software path is expected but not mounted yet, add =--no-create= to fail fast without creating that path: =eb-staged-rebuild probe --path /opt/site/software --no-create=.
For a strict readiness check, add =--require-eb= so the probe exits 1 when the EasyBuild command is missing.

** If it fails

| Message                                                                                       | Cause                                                                                    | What to do                                                                                                                                                    |
|-----------------------------------------------------------------------------------------------+------------------------------------------------------------------------------------------+---------------------------------------------------------------------------------------------------------------------------------------------------------------|
| =eb-staged-rebuild-1.0.0-x86_64-linux-musl: FAILED=, then =1 computed checksum did NOT match= | The download is damaged, or is not the release's file.                                   | Do not install it; download it again.                                                                                                                         |
| =cannot execute binary file: Exec format error=                                               | The binary is for the other architecture.                                                | Download the one =uname -m= names.                                                                                                                            |
| =error: invalid option: "commit"=, from =zig build=                                           | The commit checked out is 1.0.0 or older, whose build takes no =-Dcommit=.               | Leave =-Dcommit= out.                                                                                                                                         |
| =EasyBuild: EB was not found on PATH. Install EasyBuild and put eb on PATH, as https://docs.easybuild.io/installation/ describes, or pass --eb with its path= | =eb= is not on =PATH=, or =--eb= names a command that is not there. | Install EasyBuild from that guide and put =eb= on =PATH=, or pass =--eb= with the path of the =eb= command. |
| =bwrap: not usable= and =reason: bwrap is not installed=, from =probe=                        | bubblewrap is not installed.                                                             | Install it, or accept the next sandbox =run= finds; [[file:../explanation/isolation.org][How a build is kept off the live tree]] says what each one protects.                                        |
| =user-namespace sandbox: not usable=, from =probe=                                            | The kernel or the account does not allow user namespaces, or =unshare= is not installed. | Without bubblewrap either, =run= builds with EasyBuild's install-path options alone; see [[file:../explanation/isolation.org][How a build is kept off the live tree]].                               |
| =RENAME_EXCHANGE: no=, from =probe=                                                           | The filesystem of =--path= cannot exchange two directories in one call.                  | =run= then exchanges them with three renames, and the installation is missing for the moment between two of them; [[file:../explanation/publication.org][How a rebuild is published]] has the details. |
